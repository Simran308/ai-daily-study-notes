# 🆕 GPT-6.1 Sol: near-flagship quality at a fifth of the price

> **TL;DR**
> - OpenAI released `gpt-6.1-sol` on 2026-09-29 (DevDay). OpenAI says it nearly matches its flagship GPT-6 Astra on agentic coding, computer use and professional work, at one-fifth of Astra's token prices.
> - The API price is $2 per 1M input tokens, $0.10 per 1M cached input tokens and $10 per 1M output tokens.
> - Migrating from GPT-6 Sol is not just a string swap. `none` and `minimal` reasoning effort are gone, and tool calling needs the Responses API.

## What it is

OpenAI launched GPT-6.1 Sol on 2026-09-29 at its DevDay event. It arrived about a week after GPT-6 Sol, and the GPT-6 family is now a three-tier lineup:

- **GPT-6 Astra** is the flagship. It launched on 2026-09-03 (per DataCamp).
- **GPT-6.1 Sol** is the mid-tier "workhorse" and the newest model.
- **GPT-6 Luna** is the small, cheap model.

OpenAI did not ship a "GPT-6.1 Astra", although one was widely expected (per TechCrunch).

What's new compared with GPT-6 Sol, according to OpenAI's launch post and press coverage:

- **Capability.** It is better at coding and debugging, document understanding, computer use and multistep business workflows. On OSWorld 2.0 (a computer-use benchmark), OpenAI says it beats GPT-6 Sol by seven percentage points at maximum effort for less than half the cost per task.
- **Factuality.** At low reasoning effort, the share of responses containing a factual error dropped from 11.4% to 7.7%.
- **API shape.** Reasoning is always on. `reasoning.effort` accepts `low`, `medium` (the default), `high`, `xhigh` and `max`. `none` and `minimal` are not supported.
- **Tool calling.** Chat Completions works for plain text, but anything with tools has to go through the **Responses API**.

Every benchmark number above is **vendor-reported**. They are useful for deciding what to test, but they aren't a verdict. The New Stack reports a mixed picture against Anthropic's Claude Sonnet 5.5. On DeepSWE, Sol scores about 75% versus 71%. On AutomationBench, Sol scores about 36% versus 44.7%, though Sol costs far less per task ($0.30 versus $1.14).

## Why it matters

- **Coding agents.** It is available in Codex (`codex --model gpt-6.1-sol`) and in the API. Teams running agents all day can pay mid-tier prices for results OpenAI says are close to the flagship's.
- **Computer-use and back-office automation.** Filling forms, reconciling documents and driving internal tools are long, token-hungry loops, so cost per task matters more than cost per token.
- **Model routing.** The sensible default is now "start on Sol, escalate to Astra only for the hardest residue", and you can measure whether that holds on your own tasks.

## How it works

You don't need the model internals today. What matters is the knob you control, **reasoning effort**: how many hidden "thinking" tokens the model spends before it answers.

```
your prompt ──► [ hidden reasoning tokens ] ──► visible answer
                 ▲ low ... medium ... high ... xhigh ... max
                 │ more effort = more output tokens = more $ and more latency
```

Reasoning tokens are billed as **output tokens**, the same rule you learned in the tokens lesson. Because output costs 5x input at Sol's prices ($10 versus $2), effort is your main cost dial. A task that burns 30k reasoning tokens at `high` costs about $0.30 in thinking alone.

Two other things from OpenAI's docs:

- **Mid-conversation effort changes.** A `configuration_update` input item lets you raise or lower effort partway through a conversation without rewriting the prompt prefix, so cached prefixes stay cached.
- **Cached input is cheap.** At $0.10 versus $2, a long, stable prefix such as a system prompt or repo context is 20x cheaper to resend.

## Try it

Run the same task at three effort levels and compare the real token usage and cost.

```python
# pip install openai
import time
from openai import OpenAI

client = OpenAI()  # reads OPENAI_API_KEY from the environment
PRICE_IN, PRICE_OUT = 2.00, 10.00  # $ per 1M tokens, gpt-6.1-sol standard

TASK = """Find the bug and give the fixed function:

def moving_avg(xs, k):
    return [sum(xs[i:i+k]) / k for i in range(len(xs))]
"""

for effort in ["low", "medium", "high"]:
    start = time.time()
    r = client.responses.create(
        model="gpt-6.1-sol",
        reasoning={"effort": effort},
        instructions="You are a careful code reviewer. Be concise.",
        input=TASK,
    )
    u = r.usage
    cost = (u.input_tokens * PRICE_IN + u.output_tokens * PRICE_OUT) / 1e6
    thinking = u.output_tokens_details.reasoning_tokens
    print(f"{effort:>6} | in={u.input_tokens} out={u.output_tokens} "
          f"(thinking={thinking}) | ${cost:.5f} | {time.time()-start:.1f}s")

print("\nLast answer:\n", r.output_text)
```

You should see three lines where thinking tokens, cost and latency generally rise with effort, followed by the fix. The bug is that the last windows are shorter than `k`. On an easy task like this, the answer quality should look the same at all three levels, which is the point: don't pay for `high` when `low` is enough.

## Where it fits

| | GPT-6.1 Sol | GPT-6 Astra | Claude Sonnet 5.5 |
|---|---|---|---|
| Best for | Default for agentic coding, computer use, business workflows | Hardest reasoning, science, authorized security work (per DataCamp's advice) | Strong on AutomationBench in vendor-reported comparisons (44.7% vs about 36% for Sol, per The New Stack) |
| Cost / licence | $2 in / $0.10 cached / $10 out per 1M tokens; proprietary API | About 5x Sol's rates. $10 in / $50 out per a third-party write-up *(unverified, check OpenAI's pricing page)* | Proprietary API. Price not checked for this lesson. The New Stack reports $1.14 per AutomationBench task vs $0.30 for Sol |
| Watch out for | No `none`/`minimal` effort. Tools need Responses API. OpenAI rates it "Critical" for cybersecurity capability (per DataCamp), so expect safeguards | Cost per task adds up fast | Benchmarks are not your workload |

Worked example: a task with 20k input and 8k output tokens costs 20,000 × $2 / 1M + 8,000 × $10 / 1M = **$0.04 + $0.08 = $0.12** on Sol. At Astra's reported rates it would be about $0.60.

## Flashcards
- **Q:** What is the model ID and the standard API price of GPT-6.1 Sol?
  **A:** `gpt-6.1-sol`: $2 per 1M input tokens, $0.10 per 1M cached input tokens, $10 per 1M output tokens. It was released on 2026-09-29.
- **Q:** Where does GPT-6.1 Sol sit in the GPT-6 lineup, and what does OpenAI claim about it?
  **A:** It is the mid-tier between Astra (flagship) and Luna (small). OpenAI says it nearly matches Astra on agentic coding, computer use and professional work at one-fifth of Astra's token prices (vendor-reported).
- **Q:** Which `reasoning.effort` values does GPT-6.1 Sol accept, and what is the default?
  **A:** `low`, `medium` (default), `high`, `xhigh` and `max`. `none` and `minimal` are not supported, so code that relied on them should map to `low` and be re-tested.
- **Q:** How do you call GPT-6.1 Sol with tools (function calling)?
  **A:** Use the Responses API. Chat Completions works only for requests without tools on this model.
- **Q:** Why is reasoning effort a cost dial, and what does `configuration_update` do?
  **A:** Reasoning tokens are billed as output tokens (5x the input rate here), so higher effort costs more and takes longer. A `configuration_update` input item changes effort mid-conversation without rewriting the prompt prefix, which keeps the cache valid.
