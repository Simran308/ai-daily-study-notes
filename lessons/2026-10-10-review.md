## Part 1: Foundations (from 2026-10-03 and 2026-10-04)

**1. What's the cost formula for a single LLM call (no caching or batch)?**

<details><summary>Answer</summary>

`input_tokens × input_price / 1M + output_tokens × output_price / 1M`. Output is usually priced about 5x higher than input.

</details>

**2. What counts toward a Claude model's context window?**

<details><summary>Answer</summary>

Everything in the request: the system prompt, all messages (including tool results, images and documents) and the tool definitions. The output generated for that turn also counts, including thinking.

</details>

**3. Why wrap parts of a prompt in XML-style tags like `<document>` and `<example>`?**

<details><summary>Answer</summary>

Tags remove ambiguity about where instructions, examples and data begin and end. They also let you ask for output in tags you can parse. They reduce confusion between data and instructions, but they are **not** a security boundary against prompt injection.

</details>

**4. What is the cheapest prompt-level defence against hallucination?**

<details><summary>Answer</summary>

Give the model an explicit exit, for example "If the answer isn't in the document, reply `not found`". Then it doesn't fill the gap with a confident guess.

</details>

## Part 2: Models and reasoning (from 2026-10-05, 10-07 and 10-08)

**5. What happens if a reasoning model hits `max_output_tokens`, and why does it matter for evals?**

<details><summary>Answer</summary>

The response has `status="incomplete"` with `incomplete_details.reason="max_output_tokens"`. Reasoning tokens count toward the cap, so a low cap can leave you with little or no visible text. That makes a correct model look wrong in your eval.

</details>

**6. Why does Anthropic estimate about 75% savings over Haiku 4.5 when per-token prices fell 90%?**

<details><summary>Answer</summary>

Haiku 5.5 reportedly consumes more tokens per task, and some requests land in the pricier long-context tier (above 100k tokens). Cost per task is price per token × tokens used, so measure it on your own workload.

</details>

**7. How do you call GPT-6.1 Sol with tools (function calling)?**

<details><summary>Answer</summary>

Use the Responses API. On this model, Chat Completions works only for requests without tools.

</details>

## Part 3: Agents in production (from 2026-10-09)

**8. Why prefetch context with deterministic code instead of letting the agent look things up itself?**

<details><summary>Answer</summary>

It is cheaper and more predictable, and the model can't skip a step. Ordinary code gathers the ticket, thread and docs before the model runs.

</details>

## Bonus: connect the dots

Use the formula from card 1 and the prices from the earlier lessons. Suppose one call sends **20,000 input tokens** and gets back **2,000 output tokens** (reasoning tokens included). There is no caching, and the request stays under 100k tokens.

1. What does it cost on `gpt-6.1-sol` ($2 in / $10 out per 1M)?
2. What does it cost on Claude Haiku 5.5 ($0.10 in / $0.50 out per 1M, for requests of 100k tokens or fewer)?
3. Name one reason the cheaper model might not be cheaper per *task*.

<details><summary>Answer</summary>

1. Input: 20,000 × $2 / 1M = $0.04. Output: 2,000 × $10 / 1M = $0.02. Total: **$0.06**.
2. Input: 20,000 × $0.10 / 1M = $0.002. Output: 2,000 × $0.50 / 1M = $0.001. Total: **$0.003**, which is 20x cheaper per call.
3. Cost per task is price per token × tokens used (card 6). If the cheaper model needs more tokens, more retries or a long-tier request, the gap shrinks. Accuracy also matters: a cheap wrong answer isn't cheap. Measure both on your own test set, as in the effort-vs-cost benchmark from 2026-10-07.

</details>
