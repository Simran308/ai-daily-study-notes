# 🆕 DeepSeek V4.1 Flash 1017: open weights, 1M context, and a price list with a clock in it

> **TL;DR**
> - DeepSeek shipped **V4.1-Flash-1017** on 2026-10-17. It is a dated update to V4.1-Flash, with **MIT-licensed weights on Hugging Face** and the same `deepseek-flash` API name.
> - API price is **$0.15 / $0.60 per 1M input / output tokens off-peak**, doubling at peak, with cache hits at $0.003. The context window is 1M tokens.
> - The headline benchmarks are **vendor-reported**. DeepSeek's own table still has Claude Opus 5 ahead on some rows, so test on your own tasks before moving anything.

## What it is

On Saturday 2026-10-17, DeepSeek released **DeepSeek-V4.1-Flash-1017**. Its model card calls it a *minor update* to V4.1-Flash (the version that went live on the API on 2026-09-10). The pitch is better scores on reasoning, coding, agentic and visual benchmarks, plus **shorter outputs and faster task completion**. DeepSeek frames that as a better performance-per-cost tradeoff. The API call is unchanged: you still use the model name `deepseek-flash`, and the price did not change.

The specs, from the model card and the hosting provider Baseten:

- **552B-parameter** Mixture-of-Experts (MoE) backbone. An MoE model is split into many "expert" sub-networks, and only a few run for each token, so you pay compute for the active slice and not the whole thing.
- **8B parameters active per token while reading the prompt (prefill) and 16B while writing the answer (decoding).** That asymmetry is unusual.
- A **1M-token context window** and native image input (text and images in, text out).
- A new **Causal Encoder-Decoder** architecture with "Compressed Sparse Attention 2". Baseten says this cuts the global KV-cache footprint to about **one quarter** of the previous V4 Flash. The KV cache is the memory a model keeps for every token already in the conversation, and it is what makes very long contexts expensive to serve.
- **MIT licence**, the most permissive of the common open-weight licences. The checkpoint is reportedly FP8 (8-bit) in 48 shards *(from a secondary source, MindStudio)*.

DeepSeek also opened **Search and Fetch APIs** (web search and page retrieval for agents) at $0.75 per 1,000 calls. One secondary source says billing starts 2026-10-31 at 16:00 UTC, and the Decoder reports free access for now in tools like Claude Code and Codex. Check DeepSeek's changelog before you budget for it.

## Why it matters

- **A cheap worker for agent loops.** Most of an agent's tokens go through repetitive calls like reading files, calling tools and retrying. DeepSeek says it tuned this model for its own DeepSeek Harness and for Tencent's CodeBuddy and WorkBuddy coding tools.
- **Self-hosting with a permissive licence.** If your data can't go to a third-party API, MIT weights mean you can run it yourself with no usage restrictions. It is not small, though. At about one byte per parameter in FP8, the weights alone are roughly 550 GB (my arithmetic), so think multi-GPU server and not laptop.
- **Input-heavy pipelines.** Long documents, big codebases and repeated system prompts are where a 1M window and a cache-hit price 50x below the miss price pay off. Providers like OpenRouter and Baseten already host it if you don't want to run it.

## How it works

The idea to take away is that **the price list mirrors the architecture and the clock**.

```
            prompt (read once, 8B active)            answer (written token by token, 16B active)
 ┌───────────────────────────────────────┐   ┌──────────────────────────────────────────┐
 │ system prompt + docs + tool results   │ → │ thinking tokens + visible answer         │
 │ cache hit: $0.003   miss: $0.15 /1M   │   │ $0.60 /1M                                │
 └───────────────────────────────────────┘   └──────────────────────────────────────────┘
        all rates double during peak hours (UTC clock)
```

Three levers decide your bill:

1. **Cache hit vs miss.** DeepSeek charges $0.003 per 1M for input it has seen before and $0.15 for new input, so a hit is 50x cheaper. Keep the stable part of your prompt (system prompt, tool definitions, reference documents) at the *start* and the changing part at the end. Then the repeated prefix can be cached. This is the same trick as prompt caching on other providers.
2. **Peak vs off-peak.** Since 2026-08-16 DeepSeek has billed at two rates depending on the UTC time of day, with off-peak at half the peak price. Batch jobs, nightly evals and scheduled agents can wait for the cheap window. Look up the current windows on DeepSeek's pricing page, because I couldn't confirm them from the primary source.
3. **Thinking on or off.** The API docs show a `thinking` setting (`enabled` or `disabled`) and a `reasoning_effort` setting, and thinking is on by default. Thinking tokens are output tokens, so they cost at the $0.60 rate. This is the same cost dial as `reasoning.effort` in the GPT-6.1 Sol lessons.

Worked example, using the published off-peak rates: one workload of 1M uncached input tokens plus 200k output tokens costs 0.15 + 0.12 = **$0.27**. At peak it costs $0.54. The same tokens on GPT-6.1 Sol ($2 / $10) cost $2 + $2 = **$4.00**, roughly 15x more. Price per token isn't price per task, though. Last week's rule still applies: measure **cost per correct answer** on your own data.

What DeepSeek reports, and how far to trust it: the model card compares against Kimi K3, GLM-5.3 and Claude Opus 5, among others. Two rows I could read in full:

| Benchmark (vendor-reported) | V4.1-Flash-1017 | V4.1-Flash (Sept) | Claude Opus 5 |
|---|---|---|---|
| Humanity's Last Exam, no tools | 42.6 | 36.8 | 56.3 |
| Terminal-Bench 4.0 | 42.3 | 31.2 | 51.8 |

So it is a clear step up from its own predecessor, but on these two rows the frontier closed model still leads. Press coverage says it beats larger models on *some* coding and agent benchmarks, and those come from DeepSeek's own charts. Treat all of it as a reason to run your eval, not as a result.

## Try it

You need a DeepSeek API key in `DEEPSEEK_API_KEY`. The API is OpenAI-compatible, so the standard `openai` SDK works with a different `base_url`.

```python
# pip install openai
import os, time
from openai import OpenAI

client = OpenAI(api_key=os.environ["DEEPSEEK_API_KEY"],
                base_url="https://api.deepseek.com")

# Off-peak USD per 1M tokens (peak is 2x). Assumes every input token is a cache miss.
IN_PRICE, OUT_PRICE = 0.15, 0.60
QUESTION = ("A train leaves at 09:10 and arrives at 13:45 after stopping twice "
            "for 12 minutes each. How many minutes was it moving? Reply with just the number.")

def run(thinking: str):
    kwargs = {"reasoning_effort": "high"} if thinking == "enabled" else {}
    t0 = time.time()
    r = client.chat.completions.create(
        model="deepseek-flash",
        messages=[{"role": "user", "content": QUESTION}],
        extra_body={"thinking": {"type": thinking}},
        stream=False,
        **kwargs,
    )
    u = r.usage
    cost = (u.prompt_tokens * IN_PRICE + u.completion_tokens * OUT_PRICE) / 1e6
    print(f"thinking={thinking:8} answer={r.choices[0].message.content.strip()!r:7} "
          f"out_tokens={u.completion_tokens:5} cost=${cost:.6f} time={time.time()-t0:.1f}s")

for mode in ("disabled", "enabled"):
    run(mode)
```

The correct answer is 251 (4 h 35 min is 275 minutes, minus 24). You should see both runs answer 251, with the thinking run using noticeably more output tokens, more time and a higher cost. I haven't run this against the live API. I took the parameters from DeepSeek's quick-start docs, so if your account's response shape differs, print `r.usage` and adjust. If you run it at peak hours, double the prices in the script.

Stretch goal: reuse the harness from your effort-vs-cost benchmark, swap in `deepseek-flash`, and compare **cost per correct answer** with Claude Haiku 5.5 on your ticket-triage set.

## Where it fits

| | DeepSeek V4.1 Flash 1017 | Claude Haiku 5.5 | GPT-6.1 Sol |
|---|---|---|---|
| Best for | Cheap agent worker, long input, self-hosting | Cheap sub-agent calls in a closed API | Near-flagship quality when accuracy matters most |
| Cost / licence | $0.15 / $0.60 off-peak, $0.30 / $1.20 peak, per 1M. MIT open weights | $0.10 / $0.50 up to 100k-token requests, $0.50 / $2.50 above. Closed | $2 / $10 per 1M. Closed |
| Watch out for | Time-of-day pricing, big hardware to self-host, vendor-reported benchmarks, data goes to DeepSeek's service unless you self-host | The 100k-token price cliff, and it reportedly uses more tokens per task | Cost at scale, and reasoning effort inflating output tokens |

Haiku 5.5 is actually cheaper per token than DeepSeek for small requests. DeepSeek's advantages are the open MIT weights, the flat 1M context, and the very cheap cache hits. Whether either wins on your task is an eval question.

## Flashcards
- **Q:** What are DeepSeek V4.1-Flash-1017's release date, API model name and licence?
  **A:** Released 2026-10-17 as a dated update to V4.1-Flash. You call it with `deepseek-flash`. The weights are MIT-licensed on Hugging Face and ModelScope.
- **Q:** What is the architecture shape of V4.1 Flash, and what does "8B active for input, 16B for output" mean?
  **A:** A 552B-parameter Mixture-of-Experts model with a 1M-token context. Only part of the model runs per token: about 8B parameters while reading the prompt (prefill) and about 16B while generating (decoding).
- **Q:** What are `deepseek-flash`'s API prices, and which three factors change them?
  **A:** Off-peak per 1M tokens: $0.15 input (cache miss), $0.003 input (cache hit), $0.60 output. Peak is double. The factors are cache hit vs miss, peak vs off-peak (UTC clock) and thinking on vs off, which changes output tokens.
- **Q:** How do you structure a prompt to get cheap cache hits?
  **A:** Put the stable part first (system prompt, tool definitions, reference documents) and the changing part last, so the repeated prefix can be reused. On DeepSeek a hit costs about 1/50 of a miss.
- **Q:** Why should you not switch models just because a vendor's benchmark table looks good?
  **A:** The numbers are vendor-reported, on chosen benchmarks and harnesses. DeepSeek's own table has Claude Opus 5 ahead on rows like Humanity's Last Exam (56.3 vs 42.6). Run your own eval and compare cost per correct answer.

## Quiz
1. A nightly job sends the same 20k-token policy document plus a different customer question to `deepseek-flash` thousands of times. Which change cuts the bill most without touching quality?
   - a) Put the question first and the policy document last
   - b) Put the policy document first, keep it identical, and run the job at off-peak time
   - c) Switch thinking on for every call
   <details><summary>Answer</summary>b. An identical prefix can be a cache hit ($0.003 vs $0.15 per 1M), and off-peak is half the peak price. Option a breaks the shared prefix, and option c adds output tokens at the highest rate.</details>
2. Why is "552B parameters" a poor guide to what one call costs you on the API?
   - a) Because only a fraction of the parameters (8B or 16B) is active per token, and you are billed per token, not per parameter
   - b) Because parameter count is always secret
   - c) Because the model is billed per request, not per token
   <details><summary>Answer</summary>a. It is a Mixture-of-Experts model, so compute per token is based on the active slice. The bill is still tokens × price, split by cache state, time of day and input vs output.</details>
3. A colleague says "it's MIT-licensed, so we'll just run it on our single 24 GB GPU." What is the best reply?
   - a) MIT means it automatically shrinks to fit your hardware
   - b) The licence allows it, but at about one byte per parameter the FP8 weights are roughly 550 GB, so it needs a multi-GPU server or a hosted provider
   - c) Open weights can only be used through the vendor's API
   <details><summary>Answer</summary>b. The licence settles what you may do, not what your hardware can hold. This is why providers like Baseten and OpenRouter host open-weight models for you.</details>
