# 🔁 Saturday review: 8 cards from weeks one and two

> **TL;DR**
> - Eight cards: five older ones (Oct 3–9) and three from this week (Oct 13–16).
> - Answer each one out loud or on paper before you open its answer. Retrieving the answer is what makes it stick.
> - Common thread: the model is only one part of a system. Cost, correctness and safety are mostly decided by the code around it.

## Cards

### Card 1: Pricing (from Oct 3, `tokens-context-windows-pricing`)
**What's the cost formula for a single LLM call (no caching or batch)? Which side is usually pricier?**

<details><summary>Answer</summary>

`input_tokens × input_price / 1M + output_tokens × output_price / 1M`. Output is usually priced about 5x higher than input.

</details>

### Card 2: Prompting (from Oct 4, `prompt-engineering-that-still-matters`)
**What is the cheapest prompt-level defence against hallucination?**

<details><summary>Answer</summary>

Give the model an explicit exit, for example "If the answer isn't in the document, reply `not found`". Without one, the model tends to fill gaps with a confident guess.

</details>

### Card 3: Reasoning effort (from Oct 5, `gpt-6-1-sol`)
**Why is `reasoning.effort` a cost dial on GPT-6.1 Sol? What does a `configuration_update` input item let you do?**

<details><summary>Answer</summary>

Reasoning tokens are billed as output tokens. On Sol that is $10 per 1M, 5x the $2 input rate. Higher effort therefore costs more and takes longer. A `configuration_update` item changes effort mid-conversation without rewriting the prompt prefix, so the cache stays valid.

</details>

### Card 4: Evals (from Oct 7, `effort-vs-cost-bench`)
**A reasoning model hits `max_output_tokens`. What does the response look like, and why does that wreck an eval?**

<details><summary>Answer</summary>

The response has `status="incomplete"` with `incomplete_details.reason="max_output_tokens"`. Reasoning tokens count toward the cap, so a low cap can leave little or no visible text. A correct model then looks wrong. Count these as failures, not wrong answers.

</details>

### Card 5: Agents (from Oct 9, `stripe-minions-unattended-coding-agents`)
**Why prefetch context with deterministic code instead of letting the agent look things up itself?**

<details><summary>Answer</summary>

It's cheaper and more predictable, and the model can't skip a step. Ordinary code gathers the ticket, thread and docs before the model runs.

</details>

### Card 6: Structured outputs (from Oct 13, `structured-outputs-json-schemas`)
**What does a schema-enforced output guarantee, and what doesn't it?**

<details><summary>Answer</summary>

It guarantees the output parses and has the right fields and types. It does not guarantee that the values are correct. It also doesn't guarantee completeness (output can be truncated at `max_tokens`) or business-rule validity such as number ranges. Claude's structured outputs don't enforce numeric or string-length limits, so validate those in code.

</details>

### Card 7: Long-context pricing (from Oct 15, `muse-wonder`)
**Why is cached input especially important for a model like Muse Wonder? Put numbers on it.**

<details><summary>Answer</summary>

Long agent loops resend a growing prefix, so most input tokens can be cache hits. Cached input is $0.20 per 1M against $4 per 1M normally, so a cache hit costs 5% of the usual input price.

</details>

### Card 8: Agent safety (from Oct 16, `agent-gateway-act-as-the-user`)
**Why put a rule like "refunds over $100 need a human" in the gateway code and not only in the system prompt?**

<details><summary>Answer</summary>

A prompt rule is a request. The model can ignore it, misread it, or be tricked out of it. A code rule is enforced every time, whatever the model says.

</details>

## Connect the dots

Try to answer this before you open the note. Cards 4, 5, 6 and 8 share one idea. What is it?

<details><summary>Answer</summary>

Don't trust the model to police itself. Truncation needs a status check (4), context gathering belongs in ordinary code (5), schemas and validators check the output (6), and permissions are enforced in a gateway (8). Cards 1, 3 and 7 are the cost side of the same system. Price per token, reasoning effort and cache hits decide the bill, and you only know it by reading `usage` on your own workload.

</details>
